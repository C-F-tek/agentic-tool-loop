# Regole di utilizzo MCP per Cline AI Assistant

## Principio fondamentale
**Preferire sempre i tool MCP personalizzati rispetto ai tool nativi di Cline.**

I tool MCP offrono:
- Truncation controllata (`MAX_TEXT_CHARS`, `max_chars`, `row_limit`)
- Output strutturato (JSON, linee numerate)
- Integrazione diretta con Git, SQLite, RAG, broker HTTP
- Bounded execution con timeout e max_results

I tool nativi Cline (`read_file`, `search_files`, `list_files`, `execute_command`) sono troppo generici e non forniscono contesto strutturato.

## Tool MCP essenziali (usare sempre al posto di tool nativi)

### 1. Lettura file repository
- **MCP:** `aicarmine-codex-app` → `aicarmine_repo_read`
- **Nativo (non usare):** `read_file`
- **Perché:** Truncation controllata, contesto strutturato, integrazione diretta con Git

### 2. Ricerca nel repository
- **MCP:** `aicarmine-codex-app` → `aicarmine_repo_search` o `aicarmine_repo_rg_search`
- **Nativo (non usare):** `search_files`
- **Perché:** Ricerca strutturata con contesto, filtraggio per tipo/file

### 3. Listatura directory
- **MCP:** `aicarmine-codex-app` → `aicarmine_repo_list_files` o `aicarmine_repo_tree`
- **Nativo (non usare):** `list_files`
- **Perché:** Bounded listing, max_files, integrazione con repo root

### 4. Operazioni Git
- **MCP:** `aicarmine-git-readonly` → `aicarmine_git_readonly_log`, `aicarmine_git_readonly_show`, `aicarmine_git_readonly_diff`, `aicarmine_git_readonly_blame`
- **Nativo (non usare):** `execute_command` con `git log/diff/blame`
- **Perché:** Formato strutturato, truncation controllata, integrazione con repo state

### 5. Query SQLite
- **MCP:** `aicarmine-sqlite-readonly` → `aicarmine_sqlite_readonly_query`, `aicarmine_sqlite_readonly_schema`, `aicarmine_sqlite_readonly_list_databases`
- **Nativo (non usare):** `execute_command` con sqlite3 CLI
- **Perché:** Allowlist, row_limit, timeout, max_cell_chars

### 6. Ricerca semantica RAG
- **MCP:** `aicarmine-rag` → `aicarmine_rag_context`
- **Nativo (non usare):** `search_files` + lettura manuale
- **Perché:** Reranking BGE, chunking intelligente, integrazione con index

### 7. Esecuzione task agentic
- **MCP:** `aicarmine-agentic-loop-client` → `aicarmine_agentic_loop_run`
- **Nativo:** Nessun tool equivalente
- **Perché:** Broker HTTP, job tracking, terminal result

### 8. Validazione codice
- **MCP:** `aicarmine-codex-app` → `aicarmine_repo_validate`, `aicarmine_repo_ruff_check`, `aicarmine_repo_pyright_check`, `aicarmine_repo_pytest_run`, `aicarmine_repo_shellcheck`, `aicarmine_repo_semgrep_scan`
- **Nativo (non usare):** `execute_command` con ruff/pyright/pytest
- **Perché:** JSON diagnostics, bounded execution, repo-aware

## Workflow consigliato

### Prima di modificare un file:
1. `aicarmine_repo_read` → leggere il file effettivo
2. `aicarmine_git_readonly_diff` → controllare modifiche non commitate
3. `aicarmine_git_readonly_log` → controllare storia recente
4. `aicarmine_repo_status` → verificare stato repository

### Prima di cercare informazioni:
1. `aicarmine_rag_context` → ricerca semantica per orientamento
2. `aicarmine_repo_search` → ricerca testuale strutturata
3. `aicarmine_memory_state_packet` → recuperare stato operativo

### Prima di eseguire validazione:
1. `aicarmine_repo_ruff_check` → controllo Python
2. `aicarmine_repo_pyright_check` → controllo type checking
3. `aicarmine_repo_validate` → validazione completa

## Regole di priorità

1. **Tool MCP > Tool nativi Cline** per operazioni repository, Git, SQLite, RAG, validazione
2. **Tool MCP > execute_command** per operazioni strutturate con truncation
3. **Tool nativi Cline** solo per operazioni semplici (lettura file singolo senza contesto repository)
4. **execute_command** solo per operazioni che non hanno tool MCP equivalente

## Note

- I tool MCP hanno truncation controllata (`MAX_TEXT_CHARS`, `max_chars`, `row_limit`)
- I tool MCP integrano direttamente Git, SQLite, RAG, broker HTTP
- I tool MCP forniscono output strutturato (JSON, linee numerate) invece di output grezzo
- Non usare `read_file`, `search_files`, `list_files`, `execute_command` quando esiste un tool MCP equivalente
